## 👋 Sobre mim

QA com foco em **qualidade de ponta a ponta** — leio o requisito, desenho os cenários (inclusive bordas e falhas, não só o caminho feliz), automatizo o que se repete e mantenho manual o que exige julgamento. Valido pela UI e cruzo com a API/estado, e registro evidência clara. Tenho experiência menos comum no mercado: **QA de aplicações com IA/LLM** — avaliação de agentes conversacionais (aderência ao roteiro, drift, robustez e guardrails).

Para mim o QA não é só "achar bug", é **dar confiança para o time entregar**.

## 📂 Projetos de Teste

Cada projeto segue o mesmo padrão: **problema → abordagem → ferramentas → resultados/aprendizados → link**.

### 1. 🖐️ Teste Manual — Sauce Demo (e-commerce)
- **Problema:** validar o fluxo crítico de login e compra de uma loja, cobrindo bordas e estados de falha.
- **Abordagem:** plano de teste + casos de teste (positivos, negativos, bordas) + bug reporting com evidência.
- **Ferramentas:** teste exploratório, casos de teste em Markdown, template de bug report.
- **Resultados:** fluxo mapeado, casos documentados e um bug visual registrado (`problem_user`).
- **Link:** [`manual/`](./manual) — [plano](./manual/plano-de-teste-saucedemo.md) · [casos](./manual/casos-de-teste/login-saucedemo.md) · [bug report](./manual/bug-reports/BUG-001-imagens-trocadas.md)

### 2. 🤖 Automação UI / E2E — Playwright
- **Problema:** automatizar a regressão do login e checkout para rodar a cada mudança.
- **Abordagem:** suíte E2E com Page Objects, dados de teste parametrizados e relatório HTML.
- **Ferramentas:** Playwright (TypeScript), Page Object Model.
- **Resultados:** fluxo feliz + casos negativos automatizados, prontos para CI.
- **Link:** [`automacao-ui-playwright/`](./automacao-ui-playwright)

### 3. 🔌 Testes de API
- **Problema:** validar contratos, status codes e CRUD de uma API REST pública.
- **Abordagem:** coleção de requisições com asserções de schema, status e corpo.
- **Ferramentas:** Postman / `requests` (Python).

## 🤖 Diferencial: QA de aplicações com IA/LLM

Testar um produto com IA generativa exige avaliar a **conversa do agente**, não só a tela:
aderência ao roteiro · retenção de contexto · **drift** · robustez a variação de entrada · **guardrails** (compliance, dados sensíveis, viés).
